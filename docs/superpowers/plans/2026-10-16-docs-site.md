# tldrq Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a thorough, code-verified User Guide and Developer Guide for tldrq at https://docs.tldrq.com, built with Zensical, dark mode by default.

**Architecture:** A Zensical site in `website/tldrq/` (config + `docs/`), with uv managing Zensical through `website/pyproject.toml` and `website/uv.lock`. Two navigation tabs (User Guide, Developer Guide). Files whose contents the docs show (schema, `package.json`, workflows) are pulled in with `pymdownx.snippets` so they can't drift. A `docs.yml` workflow builds every PR that touches the docs and deploys to GitHub Pages on pushes to master.

**Tech Stack:** Zensical (latest, 0.0.70 at time of writing), uv, Python 3.13, pymdownx extensions, Mermaid, GitHub Actions, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-10-15-docs-site-design.md`

## Global Constraints

- No commits, pushes, or PRs until the user explicitly says so (user's global instruction). Tasks end with a verification step, not a commit.
- Work on a branch named `docs-site` created from `master` in the main checkout (the untracked `website/` and `docs/superpowers/` come along).
- Source of truth is the code. README, CLAUDE.md, `llms.txt` and `docs/*.md` are partly stale; never copy a claim from them without checking it against `src/`, `supabase/`, `electron/` or `.github/`. Every fact a page needs is listed in its task, with its source.
- Behavior that could not be confirmed is left out rather than guessed.
- User Guide pages: what a user sees and does, using the app's exact UI labels; no source paths (no `src/`). Developer Guide pages cite files (`src/...`) so readers can follow along.
- No screenshots or images of the signed-in app; no email addresses or personal data on any page. Flows use Mermaid.
- No version numbers that will go stale, except where the version is the point (Node 26 in CI). Versions of dependencies are shown only by including `package.json` / `electron/package.json` with snippets.
- Never write the literal snippet marker (two dashes, `8<`, two dashes) in prose: pymdownx.snippets would try to include a file. Use it only on its own line inside a code fence to include a file.
- Every page starts with front matter `icon: lucide/<name>` (as in jev4k), then one `# Title` matching its nav label.
- Mermaid fences are written as ```` ``` mermaid ````; admonitions as `!!! note`, `!!! tip`, `!!! warning`; content tabs as `=== "Label"`.
- Internal links are relative `.md` links (e.g. `[Sharing](sharing.md)`, `[Database](../developer-guide/database.md#shared_views)`); `--strict` fails on broken ones.
- Markdown pitfalls: placeholders in angle brackets (`<channel>`, `<slug>`) are read as HTML tags and vanish, so put them in code spans or write them in italics; a `|` inside a table cell ends the cell, so write `\|` or rephrase; a heading ending in `{…}` is read as an attribute list, so endpoint headings go in code spans (`` ### `PATCH /api/bookmarks/{id}` ``); keep Mermaid labels plain (no `;`, `#` or query strings).
- All commands below are run from the repository root unless a `cd` is shown.

**Progress build** (used at the end of Tasks 1–8). Pages link to pages that later tasks write, and `--strict` fails on those links, so until Task 9 each task runs a normal build and reads its warnings:

```bash
cd website/tldrq
uv run --locked python ../check_nav.py | grep -c 'missing page'
uv run --locked zensical build --clean 2>&1 | perl -pe 's/\e\[[0-9;]*m//g' | grep -A3 'Warning:'
```
Pass when the count matches the task's expected number and every warning is "page does not exist" or "anchor does not exist" for a link whose target page is written by a later task. A warning about a link into a page that already exists is a real error: fix it. From Task 9 on, the strict build (`uv run --locked zensical build --clean --strict`) must pass.

## Spec reconciliations (found while verifying the spec against the code)

These follow the spec's rule that the code wins. The user should confirm them during plan review.

1. **No public-collection toggle and no revoke button exist in the UI.** `src/components/collections/collection-menu.tsx` offers only Rename and Delete; nothing in `src/` sets `shared_views.is_active`. The Collections and Sharing pages say so plainly; the Developer Guide shows the API call (`PATCH /api/collections/{id}` with `is_public`) and the SQL (`is_active = false`) that do it.
2. **Bulk import has no size limit.** The import page describes the actual behavior (sequential, no cap) instead of "limits".
3. **Slack notifications fire on sign-in, not on bookmark creation** (`src/lib/utils/slack.ts`, called from both auth callbacks). CLAUDE.md is stale here.
4. **`zensical build --strict` does not report a nav entry whose page is missing** (tested with Zensical 0.0.70; it does fail on broken links and missing snippet files). The plan adds `website/check_nav.py`, run locally and in `docs.yml`.
5. **More files are included by snippets than the spec lists** (`package.json`, `electron/package.json`, `.github/workflows/ci.yml`, `.github/workflows/docs.yml`, `.github/dependabot.yml`, besides `supabase/schema.sql`), so `docs.yml`'s path filters list each of them.
6. **GitHub Pages is already enabled with the Actions source, and `docs.tldrq.com` already has a CNAME to `pambrose.github.io`.** The only one-time step left is setting the custom domain on the repo's Pages site. Because the DNS record already exists while no Pages site claims the domain, that step should happen soon after merge.
7. **`supabase/drop_all.sql` is stale** (drops only `bookmarks` and `collections`), and **`supabase/schema.sql` begins by dropping every application object**. The Database and Deployment pages warn about both.

```python
"""Fails when the nav in zensical.toml and the pages under docs/ disagree.

`zensical build --strict` doesn't report a nav entry whose page is missing, so
.github/workflows/docs.yml runs this before the build. Run it from website/tldrq:

    uv run --locked python ../check_nav.py
"""

import sys
import tomllib
from pathlib import Path


def nav_files(entries):
    for entry in entries:
        for value in entry.values():
            if isinstance(value, list):
                yield from nav_files(value)
            elif not value.startswith(("http://", "https://")):
                yield value


config = tomllib.loads(Path("zensical.toml").read_text())
docs = Path("docs")
listed = set(nav_files(config["project"]["nav"]))
pages = {page.relative_to(docs).as_posix() for page in docs.rglob("*.md")}

problems = [f"missing page: {path}" for path in sorted(listed - pages)]
problems += [f"page not in nav: {path}" for path in sorted(pages - listed)]
for problem in problems:
    print(problem)
sys.exit(1 if problems else 0)
```

Run: `cd website/tldrq && uv run --locked python ../check_nav.py; echo "exit=$?"`

  - Vimeo — `vimeo.com/<number>` — title — "By <author>" — thumbnail

  - Instagram — `instagram.com/p/…`, `/reel/…`, `/tv/…` — from the page's preview tags — from the page — from the page
  - Everything else — the page's Open Graph title (or `<title>`) — Open Graph description (or meta description) — Open Graph image
- GitHub or GitLab pages that aren't a repository (a profile or organization page), or a repository the API can't return, fall back to the page's preview tags like any other site.

- Repository stats: stars, forks, and for GitHub the main language (for GitLab, the project's first topic is shown in that spot). Counts of 1,000 or more read `1.2k`; a million or more `1.2m`. (`repo-stats.tsx`)
